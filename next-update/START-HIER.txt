ARENA ROBLOX BRIDGE — START HIER (Version 7.9.0)
=================================================

NUR BAUEN UND TESTEN?

1. Oeffne den Ordner next-update.
2. Doppelklicke Build-EXE.bat.
3. Warte auf BUILD ERFOLGREICH.
4. Starte genau diese EXE:

       release\ArenaBridge.exe

   Vorher andere ArenaBridge-Fenster schliessen. Falls beim Start kein Fenster
   erscheint, schliesse andere ArenaBridge-Prozesse und starte
   release\Start-Diagnostic.bat. Das Diagnose-Fenster offen lassen.

ZUM VEROEFFENTLICHEN (nur wenn der Test gut war):

- Lade die getestete Datei als next-update\release\ArenaBridge.exe auf main hoch
  (ersetzen). Die Version in der EXE muss neuer sein als die bisherige.
- GitHub startet dann automatisch den Workflow "Bridge-Version veroeffentlichen"
  (Reiter Actions). Er schreibt next-update\release\latest.json. Erst danach
  sehen Nutzer das Update.
- Ist der Workflow rot: Meist ist die Version nicht erhoeht. Sag der KI
  "Version erhoehen" — sie setzt dann z. B. 7.9.1 in app\version.json.

WIE DAS UPDATE FUER NUTZER FUNKTIONIERT:

- Beim Start prueft die Bridge (hoechstens 5 Sekunden), ob eine neue Version da ist.
- Ist sie da, erscheint das Fenster "Update verfuegbar" mit dem gruenen Knopf
  "Jetzt installieren". Er oeffnet den Browser mit der neuen EXE.
- "Spaeter" wird gezaehlt (ueber alle Starts). Nach 5 Klicks gibt es keinen
  "Spaeter"-Knopf mehr, das Update ist dann Pflicht.
- Die neue EXE schiebt beim ersten Start die alte EXE in den Papierkorb.
- Ohne Internet startet die Bridge ganz normal.

WICHTIG:

- Die Bridge ersetzt sich nie selbst. Die neue EXE startest du selbst.
- Windows kann beim Herunterladen warnen ("Unbekannter Herausgeber" /
  SmartScreen). Die EXE ist nicht signiert. Wenn du der Datei vertraust:
  "Weitere Informationen" -> "Trotzdem ausfuehren".
- Der Ablauf im Detail: README.md. Technik: developer\docs\UPDATE-SYSTEM.md.
